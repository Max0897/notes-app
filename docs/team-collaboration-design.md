# 备忘录多人协作设计方案

状态：2026-10-15 已获用户批准；按用户最新要求调整为纯备忘录协作，团队沿用个人空间的列表、文件夹和编辑器。此文档记录当前范围与验收规则。

## 1. 首期范围

引入「个人空间 / 团队空间」，保留当前三栏结构。一个账号可加入多个团队；个人备忘录默认私有，团队资料归团队所有，成员离开后仍保留。

首期交付团队创建、修改、解散与恢复、邀请与成员管理、文件夹权限、共享备忘录、活动记录、多人编辑冲突保护，以及桌面和手机适配。

团队多人编辑现已按用户批准的后续方案升级为 Yjs 实时合并：标题、正文、光标与选区同步，显示在线成员头像和昵称。个人空间继续使用版本冲突保护；现已补充整篇评论、成员提及、历史版本、恢复草稿、直接链接与文字导入导出。

## 2. 页面与入口

- 左上角品牌下方增加空间切换器：下拉菜单依次显示个人空间、已加入的团队，最后一项为「创建团队」。切换前先保存当前编辑，保存失败则停留。
- 团队空间左侧显示所有备忘录、已置顶、文件夹、最近删除；底部头像上方依次提供「团队设置」「团队邀请」「通知中心」，使用相同的图标加文字入口，点击进入各自独立页面并高亮当前入口。「团队设置」仅在团队空间显示；手机端页面提供导航抽屉入口。
- 中栏继续显示搜索、默认勾选框、新建与更多菜单；右键及批量移动都只列出当前空间内有编辑权限的目标。
- 右侧编辑区的保存状态左侧显示最后修改人、只读标记及其他正在编辑此篇的成员提示；正文上方显示修改时间。
- 左下角头像上方提供「通知中心」，进入独立页面查看按时间倒序排列的个人与团队事件，自动标记已有通知为已读，并支持分页；团队通知按接收对象和当前权限校验，邀请令牌不进入消息。
- 团队设置分为：基本信息、成员、邀请、文件夹权限、活动记录。普通成员仅显示其可使用的页签与操作。
- 手机端复用现有抽屉导航；右键功能提供可点击的更多入口，文件夹二级菜单支持点击展开。

## 3. 角色与权限

每个团队恰好一名所有者；邀请默认授予查看者，邀请时可改为编辑者。

| 能力 | 所有者 | 管理员 | 编辑者 | 查看者 |
| --- | --- | --- | --- | --- |
| 查看备忘录、搜索 | 全部 | 全部 | 获授权范围 | 获授权范围 |
| 新建、编辑、置顶、移动、软删除备忘录 | 全部 | 全部 | 有编辑权限的范围 | 否 |
| 恢复备忘录 | 全部 | 全部 | 有编辑权限的范围 | 否 |
| 新建、重命名、删除文件夹及设置权限 | 是 | 是 | 否 | 否 |
| 修改团队名称、简介 | 是 | 是 | 否 | 否 |
| 邀请、调整或移除编辑者与查看者 | 是 | 是 | 否 | 否 |
| 任命、降级、移除管理员 | 是 | 否 | 否 | 否 |
| 查看完整活动记录、永久删除资料 | 是 | 是 | 否 | 否 |
| 解散和恢复团队 | 是 | 否 | 否 | 否 |

管理员不能修改所有者或其他管理员的身份。普通成员可主动退出；所有者不能退出或被移除，可解散团队。

### 文件夹权限规则

首期沿用现有单层文件夹，支持「团队可见」和「指定成员可见」两种范围。

- 团队可见：普通成员按其团队角色获得查看或编辑权限。
- 指定成员可见：仅被添加的成员可访问，逐人设置「查看」或「编辑」；未被添加的成员不可通过搜索、列表、数量、最近删除或直接读取接口看到其中资料。
- 成员角色是权限上限：查看者不能通过文件夹授权升级为编辑者；编辑者可在特定文件夹被降为只读。
- 所有者和管理员始终有团队内全部资料权限，设置界面明确说明这一点。
- 备忘录继承所属文件夹权限；未分类备忘录采用团队默认权限。首期不提供单篇例外，避免规则叠加。
- 修改文件夹权限会影响其中所有备忘录；保存前显示影响范围。
- 移动资料必须同时拥有源位置与目标位置的编辑权限，并提示将继承目标权限。批量操作任一资料无权限或版本冲突时，整批不执行。
- 删除受限文件夹时，其资料整体移入最近删除，并保留原访问范围；不能通过移至公共未分类而扩大可见范围。恢复文件夹后资料回到原位置。

示例：小王是团队编辑者，在「产品计划」可编辑，在「财务资料」仅可查看；小李未被加入「财务资料」，在任何入口都看不到其中内容。

## 4. 团队生命周期

### 创建与编辑

创建时填写团队名称（2–40 字）和可选简介（最多 200 字）。空间切换器中的团队统一使用成员图标，表单不提供图标选择。创建者成为所有者。重名允许，通过团队 ID 区分；团队设置显示创建人、创建时间和成员数量。

### 邀请与加入

提供两种方式，不依赖目前系统尚未配置的邮箱服务：

1. 按完整用户名发送站内邀请。对方在「收到的邀请」接受或拒绝；接受前不获得团队资料权限。
2. 创建邀请链接，默认 7 天有效、限加入 1 人、默认查看者。生成时可选择编辑者权限；接收者登录或注册后看到团队与邀请人信息，明确点击接受后加入。

管理员列表展示邀请状态：待接受、已接受、已拒绝、已撤销、已过期。支持撤销及重新邀请；重新邀请产生新令牌，旧链接不恢复。不得通过邀请链接授予管理员或所有者身份。

接受邀请时重新检查团队状态、邀请有效期、角色配置、使用次数及成员身份，并在事务中完成；重复点击不会重复加入。站内邀请只能由指定账号接受，链接只保存令牌哈希，限制生成和尝试频率。

### 成员管理与退出

成员列表展示头像、用户名、角色、加入时间，可搜索、调整权限、移除成员。降级、移除及撤销邀请即时生效；已打开页面收到变化通知，服务端每次读取、保存、搜索、移动及删除都重新校验权限。

成员退出或被移除后，团队内其创建的资料仍归团队，保留作者信息；个人空间不受影响。

### 解散与恢复

团队设置中的「解散团队」须输入团队名称并验证当前密码，说明影响。解散后停止邀请及全部普通访问，进入 30 天可恢复期；仅当时的所有者可在「已解散团队」中恢复，历史邀请仍作废。恢复后成员关系、资料与权限一并恢复。

30 天后按维护任务清理团队资料；所有者可在恢复期内恢复后重新管理。团队删除不会删除任何成员账号或个人空间资料。

## 5. 共享备忘录流程

团队空间与个人空间使用相同的三栏布局、备忘录卡片和富文本编辑器，团队功能围绕成员协作与权限展开。

- 成员在有编辑权限的位置新建、编辑、置顶和移动备忘录；查看者可阅读及搜索。
- 默认勾选框、更多菜单和右键菜单保持现有操作习惯，支持单篇和批量操作。
- 团队内移动继承目标文件夹权限，操作前提示影响；任何一篇权限不足或版本冲突时整批不执行。
- 删除与恢复保留正文、原文件夹和权限来源；受限文件夹删除后，其备忘录不能通过最近删除扩大可见范围。
- 切换到团队空间后直接新建团队备忘录，按团队角色及文件夹权限与成员协作。
- 团队备忘录与协作数据统一保存在 SQLite 中，沿用个人空间的备份方式。

## 6. 多人编辑行为

- 团队备忘录按团队 ID 和备忘录 ID 建立独立 Yjs 文档，通过 Hocuspocus WebSocket 实时合并标题与正文；正文撤销只影响本人操作，StarterKit 默认历史关闭。
- SSE 继续刷新列表和成员权限；WebSocket 每次消息重新检查有效会话、团队角色及文件夹权限，API 变更后立即复查现有连接，每秒另做一次过期检查。
- 编辑器显示最多 4 个在线成员头像及 `+N`，同一账号多个窗口的头像合并；查看者参与在线展示，不能上传文档修改或编辑光标。光标、选区与头像边框使用服务器分配的颜色，姓名与头像来自已认证账号。
- Awareness 临时同步光标、选区和正在编辑／查看状态，不写入数据库，不作为互斥锁；正常离开即移除，异常断线由心跳超时清理。客户端以 50ms 窗口合并文档和状态消息。
- 服务端在确认和广播修改前校验正文结构及大小，将 Yjs 状态与 JSON／纯文本快照在同一事务内保存。只有收到与本地文档快照（包含删除记录）一致的落盘回执后才显示「已保存」；Ctrl/Cmd+S 立即发送待同步修改并等待回执。
- 已打开页面的断线修改保留在内存与按账号隔离的浏览器恢复草稿中，刷新后恢复连接会合并；离开前等待保存，未同步时关闭页面有提示。
- 权限被收回或团队解散时，立即阻止新请求及保存，关闭内容页；若已有尚未保存的本地输入，显示无法保存的说明并提供复制草稿机会，不自动写入个人空间或其他团队。
- 支持整篇评论、评论回复和成员提及通知；回复归属原评论讨论串，被回复人收到通知，查看者仅可阅读；评论与历史版本接口均继承当前文件夹权限。历史恢复以新编辑更新原有 Yjs 文档，不重置协作状态；恢复前保留当前快照，版本不匹配时拒绝恢复。

## 7. 技术落地与兼容

保持现有 React、Arco Design、Hono、SQLite 架构，引入独立空间归属与统一权限校验。

| 数据实体 | 用途 |
| --- | --- |
| spaces | 个人／团队空间标识，成为内容的统一归属边界 |
| teams | 团队名称、简介、所有者、解散时间及配置 |
| team_members | 团队与用户的唯一成员关系、角色及加入时间 |
| team_invitations | 邀请对象、令牌哈希、角色、有效期及状态 |
| folder_access | 文件夹可见范围及成员查看／编辑授权 |
| activity_logs | 团队管理、权限、移动、删除、恢复等事件 |
| collaboration_documents | 按备忘录保存 Yjs 二进制状态，随备忘录永久删除级联清理 |
| note_history | 标题、富文本与修改人快照，最多 100 个，恢复前保留当前内容 |
| note_comments | 整篇评论、讨论串及回复对象、提及成员与标签位置，随备忘录永久删除级联清理 |

现有笔记与文件夹迁移到各自的个人空间，保留原 ID、正文、版本和账号会话。将原 user_id 的职责拆为内容所属空间及创建／修改人；新增跨表空间一致性检查，不能仅用创建者判断团队权限。

所有列表、搜索、计数、读取、批量修改、最近删除及事件订阅都经过相同的权限规则；写入时在事务中重新校验有效成员关系与源／目标权限。用户不能通过猜测 ID 或批量接口访问其他空间。

个人与团队备忘录各自在所属空间内创建和维护。「移动到」仅在当前空间内操作。

旧团队备忘录首次进入协作时在服务器播种一次，客户端同步前不挂载正文编辑器，避免重复初始化。启用协作后，原整篇 PATCH 接口拒绝标题／正文修改，置顶、移动和删除继续使用版本校验。协作状态成为正文唯一来源，JSON／纯文本只作派生快照。WebSocket 复用当前 HTTP 端口的 `/api/collaboration` 路径，握手校验 Origin 和 HttpOnly 会话；当前只支持单实例部署。

活动记录覆盖团队生命周期、邀请、成员角色变更、权限变更、资料创建／移动／删除／恢复，包含操作者、时间、对象及动作；不记录密码、邀请令牌或完整正文。正文历史快照独立存储，最多保留 100 个，连续编辑按分钟合并；自动保存不逐次写入活动日志。

## 8. 验收标准

1. 老账号升级后仍可正常登录，个人资料、头像、快捷键和现有菜单可用。
2. 四类角色与所有入口的权限一致，隐藏资料不会从搜索、计数、直接读取或事件通知泄露。
3. 邀请接受前无访问权；撤销、过期、重复接受及并发接受行为正确。
4. 移除或降级成员后，其旧页面和请求不能继续越权读写。
5. 文件夹权限变更与资料移动正确继承权限；同一批次失败不出现部分写入。
6. 团队与个人使用同一备忘录列表和编辑器；移动、批量删除与恢复保留正文和原文件夹；新数据库仅创建备忘录协作所需的数据表。
7. 两名成员同时修改同一篇的标题和正文时自动合并；光标与选区跟随文字变化，重连和重启后内容一致；只读者无法通过底层 CRDT 写入，旧整篇 PATCH 不覆盖协作状态。
8. 解散后全部普通访问失效，所有者可在保留期恢复；恢复不使旧邀请重新生效。
9. 桌面与 320px 手机宽度下可完成邀请、权限配置及资料操作。

## 9. 当前范围与默认值

当前范围采用：四角色；团队默认共享＋文件夹限制；站内用户名邀请和 7 天单次邀请链接；共享备忘录与实时协作；解散保留 30 天；元数据版本冲突保护；个人与团队备忘录独立管理。

用户已批准团队协作及后续实时协作开发，并明确要求团队空间仅管理备忘录与文件夹。用户已进一步批准昵称与六项效率功能：历史版本、恢复草稿、评论和提及、直接链接、搜索优化、文字导入导出；操作说明见 README。
